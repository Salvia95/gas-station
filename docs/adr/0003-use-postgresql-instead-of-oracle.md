# ADR-0003: 관계형 데이터베이스로 PostgreSQL 채택

## Status

Accepted

## Context

레거시 시스템의 데이터베이스는 상용 데이터베이스인 Oracle을 RAC(Real Application Clusters) 구성으로 사용하고 있다. RAC를 통해 다수의 인스턴스가 동일한 스토리지를 공유하며 전체 인스턴스에 대한 데이터 일관성을 유지하고 있다.

현재 시스템에서 발생하고 있는 주요 문제점은 다음과 같다:

- **높은 라이선스 비용**: Oracle의 라이선스 비용이 높아, 컴퓨팅 자원 확장 시 비용이 급증한다.
- **벤더 종속성**: Oracle 전용 문법(PL/SQL, 힌트 등)으로 작성된 프로그램의 마이그레이션에 제약이 있다.
- **현대적 개발 환경과의 충돌**: 컨테이너 환경 지원이 제한적이고 ORM과의 호환성이 완벽하지 않아 현대적인 개발 방식과 충돌한다.

MySQL도 오픈소스 대안으로 고려되었으나, Oracle에서의 마이그레이션 관점에서 문법적 유사도가 낮아 쿼리 로직 변환과 학습 곡선 면에서 부적합하다고 판단했다.

## Decision

관계형 데이터베이스를 Oracle에서 **PostgreSQL**로 변경한다.

PostgreSQL을 선택한 이유는 다음과 같다:

1. **Oracle과의 문법적 유사성**: Oracle과 유사한 SQL 문법을 가지고 있어 레거시 시스템 담당자의 학습 부담이 적고, 기존 쿼리 마이그레이션이 용이하다.
2. **비용 효율성**: 오픈소스이기에 라이선스 비용 부담 없이 자유롭게 확장할 수 있다.
3. **유연한 데이터 모델링**: JSON/JSONB 타입을 네이티브로 지원하여 유연한 데이터 모델링이 가능하다.
4. **현대적 개발 환경 지원**: Docker 환경과 JPA 모두 완벽히 지원하여 현대적 개발 환경에 적합하다.
5. **확장성**: 파티셔닝, Logical Replication 등 엔터프라이즈급 기능을 기본 제공한다.

## Consequences

### 긍정적 영향

- 라이선스 비용이 사라져 TCO(Total Cost of Ownership)가 크게 감소한다.
- Docker 기반 개발 환경 구성이 용이해져 개발 생산성이 향상된다.
- JPA/Hibernate와의 완벽한 호환으로 ORM 활용에 제약이 없다.
- JSON/JSONB를 활용한 유연한 스키마 설계가 가능해진다.
- 풍부한 오픈소스 생태계(pgAdmin, pg_stat_statements 등)를 활용할 수 있다.

### 부정적 영향

- Oracle RAC와 같은 수준의 고가용성 구성을 위해서는 별도의 아키텍처 설계가 필요하다.
- Oracle 전용 기능(Hint, PL/SQL 패키지 등)을 사용한 부분은 재작성이 필요하다.
- Oracle에 익숙한 DBA의 PostgreSQL 학습 비용이 발생한다.
- 일부 Oracle 고유 함수의 경우 PostgreSQL 호환 함수로 변환이 필요하다.

### 중립적 영향

- MVCC 구현 방식이 Oracle의 Undo 방식과 다르므로, 동시성 처리 특성에 대한 이해가 필요하다.
- Vacuum 프로세스에 대한 튜닝과 모니터링이 필요하다.
