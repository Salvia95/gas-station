# ADR-0002: 웹프레임워크로 Spring Boot 채택

## Status

Accepted

## Context

레거시 시스템은 웹프레임워크로 Spring Framework 5를 래핑한 상용 프레임워크(BX Framework)를 사용하고 있다. 이로 인해 다음과 같은 문제가 발생하고 있다:

- **벤더 종속성**: Spring과 관련된 모든 설정이 프레임워크 벤더사에 전적으로 의존하고 있어, 벤더사가 정한 특정 형식의 설정을 벗어날 수 없다.
- **업그레이드 제약**: Spring의 메이저 업데이트로 인한 설정 변경이 필요할 시 벤더사의 대응을 기다려야 하며, 자체적인 반영이 사실상 불가능하다.
- **기능 제한**: Spring AOP, AspectJ 등 Spring의 핵심 기능을 사용할 수 없어, Spring의 이점을 충분히 누리지 못하고 있다.
- **배포 방식**: 상용 서블렛 컨테이너 솔루션인 JEUS를 통해 전체 서비스를 일괄 배포하고 있어, 개별 서비스의 독립적 배포가 불가능하다.

## Decision

웹프레임워크를 상용 프레임워크에서 **Spring Boot**로 변경한다.

Spring Boot를 선택한 이유는 다음과 같다:

1. **벤더 독립성**: 오픈소스 기반으로 특정 벤더에 종속되지 않으며, 커뮤니티와 Spring 팀의 지속적인 지원을 받을 수 있다.
2. **설정 자율성**: Convention over Configuration 원칙에 따라 기본 설정을 제공하면서도, 필요시 모든 설정을 자유롭게 커스터마이징할 수 있다.
3. **독립 실행 가능**: 내장 톰캣을 통해 별도의 WAS 없이 독립적으로 실행 가능하며, 도메인 단위 배포가 가능해진다.
4. **Spring 생태계 완전 활용**: AOP, Security, Data 등 Spring의 모든 기능을 제약 없이 사용할 수 있다.
5. **현대적 개발 지원**: Actuator, DevTools 등을 통해 모니터링, 개발 생산성 향상 도구를 기본 제공한다.

## Consequences

### 긍정적 영향

- Spring의 모든 기능(AOP, AspectJ 등)을 제약 없이 활용할 수 있다.
- 도메인 단위의 독립적 배포가 가능해져 서비스 간 독립성이 확보된다.
- Spring Boot의 Auto Configuration으로 초기 설정 부담이 크게 감소한다.
- 풍부한 커뮤니티 자료와 레퍼런스를 활용할 수 있다.
- Spring Boot Actuator를 통한 운영 모니터링이 용이해진다.

### 부정적 영향

- 기존 상용 프레임워크에 익숙한 개발자들의 Spring Boot 학습 비용이 발생한다.
- 상용 프레임워크에서 제공하던 일부 편의 기능을 직접 구현하거나 대체 라이브러리를 찾아야 한다.
- JEUS 기반 인프라에서 내장 톰캣 기반으로의 전환에 따른 운영 프로세스 변경이 필요하다.

### 중립적 영향

- 기존 시스템과의 연동을 위한 별도의 인터페이스 레이어가 필요할 수 있다.
- 배포 방식의 변경으로 CI/CD 파이프라인 재구성이 필요하다.
