# ADR-0007: 서비스 간 통신으로 비동기 이벤트 채택

## Status

Accepted

## Context

레거시 시스템은 서비스 간 통신 시 타 업무 도메인의 객체에 대한 의존성을 주입하고 직접 호출하는 방식을 사용하고 있다.

이로 인해 다음과 같은 문제가 발생하고 있다:

- **높은 결합도**: 도메인 간 직접 의존으로 단 하나의 도메인에서 발생한 오류가 전체 서비스를 마비시키는 상황이 발생한다.
- **동기 호출로 인한 성능 저하**: 타 업무 도메인 호출이 모두 동기 형식으로 구현되어 있어, 다수의 도메인에 연계가 필요한 서비스는 과도한 대기 시간을 가져 큰 성능 하락이 발생한다.
- **변경 영향 전파**: 한 도메인의 인터페이스 변경이 호출하는 모든 도메인에 영향을 미친다.

대안으로 **RabbitMQ**, **Kafka** 등의 메시지 큐도 고려되었으나 다음 이유로 미채택했다:

- 기존 동기 호출 기반의 통신 방식에서도 모든 트래픽을 처리할 수 있었다.
- 단순한 이벤트 소싱 관점에서는 버퍼 캐시만 충분히 확보된다면 RDBMS 기반 Outbox를 적용한 Event Bus 구성과 성능 면에서 큰 차이가 없다.
- 별도의 클러스터 구축이 필요하여 인프라 운영 부담이 가중되고, 다중 오류 지점이 발생한다.
- SAGA 패턴을 적용할 정도의 기술적 성숙도에 도달하지 않았다.

## Decision

서비스 간 통신 방식을 동기 함수 호출에서 **Application Context 기반 비동기 이벤트 통신**으로 변경한다.

**Spring Modulith의 Event Publication** 기능을 활용하여 다음과 같이 구현한다:

1. **ApplicationEventPublisher 활용**: Spring의 이벤트 발행 메커니즘을 통해 모듈 간 이벤트를 발행한다.
2. **@Async 비동기 처리**: 이벤트 리스너를 비동기로 실행하여 발행자의 대기 시간을 제거한다.
3. **Event Publication Repository**: Spring Modulith의 Event Publication 기능으로 분산 인스턴스 환경에서의 이벤트 전달을 보장한다.
4. **트랜잭션 경계 분리**: @TransactionalEventListener를 활용하여 트랜잭션 커밋 후 이벤트가 처리되도록 한다.

## Consequences

### 긍정적 영향

- 도메인 간 결합도가 크게 감소하여 한 도메인의 오류가 다른 도메인으로 전파되지 않는다.
- 비동기 처리로 응답 시간이 개선되고, 다수 도메인 연계 시 병렬 처리가 가능해진다.
- 이벤트 기반 설계로 도메인 간 인터페이스 변경 영향이 최소화된다.
- 별도 인프라 구축 없이 애플리케이션 레벨에서 이벤트 통신을 구현할 수 있다.
- Spring Modulith의 Event Publication으로 이벤트 발행 실패 시 재시도가 가능하다.

### 부정적 영향

- 이벤트 기반 설계에 대한 학습과 사고 방식의 전환이 필요하다.
- 이벤트 순서 보장이 필요한 경우 추가 설계가 필요하다.
- 디버깅과 트레이싱이 동기 호출에 비해 어려워진다.
- Eventual Consistency에 대한 이해와 대응 전략이 필요하다.

### 중립적 영향

- 이벤트 스키마 버전 관리 전략 수립이 필요하다.
- 향후 트래픽 증가 시 외부 메시지 큐로의 전환 경로를 열어둔다.
- 이벤트 모니터링 및 Dead Letter Queue 처리 방안 수립이 필요하다.
